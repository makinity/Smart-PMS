# Smart Dashboard Plan — Smart PMS

## Overview

Every dashboard has two versions: **Normal** (existing) and **Smart** (ML-powered).
The system automatically shows the Smart version when the ML API is online, and falls back
to the Normal version when it is offline. No toggle, no user action required.

### Behaviour (same pattern as AssignModal)

```
Dashboard mounts
    → call ML API to check status + fetch scores
    → show loading spinner
    → ML online?  YES → render Smart Dashboard
                  NO  → render Normal Dashboard (silent fallback)
```

### Status indicator (shown in dashboard header)

```
● AI ONLINE   — Smart Mode active, showing ML-powered insights
● AI OFFLINE  — Showing standard dashboard
```

No toggle button. The pill is informational only.

### Auto-refresh

Dashboard does **not** auto-refresh when ML comes online mid-session.
A page reload is required to switch from Normal → Smart.
(Can be upgraded later with polling if needed.)

## ML Data Available Per Dashboard

All smart dashboards consume data from the existing FastAPI endpoints:

| Endpoint | Returns |
|---|---|
| `GET /ml/status` | `{ ml_online: bool }` |
| `GET /supervisor/uwp/suggestions?indicator_id=&period_id=` | `{ ml_online, recommendations: [{ employee_id, fit_score, risk_level }] }` |

Additional endpoints to be built in FastAPI for dashboard use:

| Endpoint | Returns |
|---|---|
| `GET /ml/employee-scores?employee_id=&period_id=` | All indicator scores for one employee |
| `GET /ml/team-scores?supervisor_id=&period_id=` | All scores for supervisor's team |
| `GET /ml/office-scores?office_id=&period_id=` | All scores for an office |
| `GET /ml/org-scores?period_id=` | All scores org-wide |
| `GET /ml/coaching-message?employee_id=&period_id=` | LLM-generated coaching message |
| `GET /ml/team-summary?supervisor_id=&period_id=` | LLM-generated team summary |
| `GET /ml/office-summary?office_id=&period_id=` | LLM-generated office summary |
| `GET /ml/org-summary?period_id=` | LLM-generated executive summary |

LLM messages are **generated once after training and cached** in `ml_coaching_messages` table.
Laravel reads from DB — never calls LLM directly.

## Implementation Notes

### Frontend pattern (all dashboards)

```jsx
export default function Dashboard() {
    const [mlOnline, setMlOnline] = useState(null); // null = loading
    const [mlData, setMlData]     = useState(null);

    useEffect(() => {
        axios.get('/api/ml/dashboard-data')
            .then(({ data }) => { setMlOnline(data.ml_online); setMlData(data); })
            .catch(() => setMlOnline(false));
    }, []);

    if (mlOnline === null) return <LoadingSpinner />;
    if (!mlOnline) return <NormalDashboard />;
    return <SmartDashboard data={mlData} />;
}
```

### Status pill (reusable)

```jsx
<span style={{
    display: 'flex', alignItems: 'center', gap: '0.4rem',
    fontSize: '0.72rem', fontWeight: 600,
    color: mlOnline ? 'var(--admin-accent)' : '#f87171',
}}>
    <span style={{ fontSize: '0.78rem' }}>●</span>
    {mlOnline ? 'AI ONLINE — Smart Mode' : 'AI OFFLINE'}
</span>
```

### LLM message caching (DB table)

```sql
ml_coaching_messages
    id
    target_type   -- 'employee' | 'team' | 'office' | 'org'
    target_id     -- employee_id / supervisor_id / office_id / null
    period_id
    message       -- LLM-generated text
    generated_at
    created_at
```

Messages are written by FastAPI after each training run.
Laravel reads them via a simple `GET /api/ml/coaching-message?type=employee&id=X&period_id=Y`.
